# 잠수크래프트 클라우드 서버 — 설치·운영 안내

폰 대신 **서버 컴퓨터가 마인크래프트 서버에 접속해 있는** 방식입니다. 폰을 끄거나 앱을 지워도, 직접 끊거나 서버에서 내보내지 않는 한 계속 접속해 있습니다.
앱과 웹이 같은 잠수를 같이 보고 조작합니다.

```
 폰 앱 ─┐                         ┌─ 마인크래프트 서버 A
        ├─(HTTPS)─ 클라우드 서버 ─┤
 웹 ────┘   (이 프로그램, 24시간)  └─ 마인크래프트 서버 B
```

- 클라우드 서버는 앱과 **같은 엔진(core)** 으로 만들어져 있고 **버전 번호도 앱과 같습니다.** 앱이 업데이트될 때 서버용 파일도 같이 만들어집니다.
- 프로그램 위치: 저장소의 `cloud/` (웹 화면은 `cloud/src/main/resources/web/`)
- 컴퓨터 한 대로 시작하면 됩니다. 나중에 컴퓨터를 더 붙여 잠수를 나눠 돌릴 수 있습니다 → 16번 "접속용 서버 붙이기" (v2.1.0~)

---

## 1. 준비물
- 24시간 켜 둘 컴퓨터 (윈도우·리눅스·맥 모두 가능)
- **자바 17 이상** — 업로드 키를 만들 때 쓴 Temurin 17 이면 됩니다 (`java -version` 으로 확인)
- 인터넷에 공개하려면 **HTTPS** 가 꼭 필요합니다 → 6번 참고 (집 안에서만 시험할 때는 없어도 됨)
- Mojang 승인을 받은 **client ID** (앱과 같은 값: `9f60141c-29ac-4d71-8fa1-f89e32a085e7`)

메모리는 시험 환경에서 기본 약 230MB, 잠수 하나를 더할 때마다 수 MB 정도였습니다. 실제 서버는 지형 데이터 때문에 더 쓸 수 있으니(잠수 하나에 20~45MB 로 잡으면 안전) 여유 있게 잡으세요.
자바는 따로 정해 주지 않으면 **컴퓨터 메모리의 1/4 까지만** 씁니다. 잠수를 많이 돌릴 컴퓨터는 실행 전에 환경 변수 `JAVA_OPTS` 로 늘려 주세요 (16GB 컴퓨터라면 `JAVA_OPTS=-Xmx10g` 정도. 윈도우: `set JAVA_OPTS=-Xmx10g`, 리눅스: `export JAVA_OPTS=-Xmx10g`).

## 2. 받기
GitHub 릴리스(https://github.com/lhj080902/jamsuham/releases)의 최신 빌드에서 **`jamsu-cloud.zip`** 을 받아 원하는 폴더에 풉니다.

```
jamsu-cloud/
  README.txt             ← 처음 설치하는 사람이 차례로 따라 하는 안내 (자바 설치부터, 자주 겪는 문제 포함)
  ASK-CLAUDE.txt         ← 막혔을 때 통째로 클로드(claude.ai)에 붙여 넣어 물어보는 질문지
  docs/CLOUD.md          ← 이 문서
  bin/jamsu-cloud        ← 리눅스·맥 실행 파일
  bin/jamsu-cloud.bat    ← 윈도우 실행 파일
  lib/                   ← 프로그램
```

## 3. 처음 실행
압축을 푼 `jamsu-cloud` 폴더에서 실행합니다.

윈도우 (명령 프롬프트):
```bat
bin\jamsu-cloud.bat
```

리눅스·맥:
```bash
bin/jamsu-cloud
```

처음 실행하면 같은 폴더에 **`cloud.properties`**(설정)와 **`data/`**(데이터)가 생깁니다.
1. 창을 닫아 서버를 끄고(Ctrl+C), `cloud.properties` 를 메모장으로 열어 `msClientId=` 뒤에 client ID 를 적습니다.
2. 다시 실행합니다.
3. 그 컴퓨터의 브라우저에서 **http://localhost:8787** 을 열면 웹 화면이 나옵니다.

## 4. 설정 (`cloud.properties`)
| 항목 | 뜻 | 기본값 |
|---|---|---|
| `port` | 웹 주소의 포트 | 8787 |
| `bind` | `127.0.0.1` = 이 컴퓨터 안에서만 / `0.0.0.0` = 같은 공유기의 다른 기기에서도 | 127.0.0.1 |
| `msClientId` | 마이크로소프트 로그인용 client ID (앱과 같은 값) | (비어 있음) |
| `trustProxy` | 앞에 Caddy·Cloudflare 터널이 있으면 true | true |
| `clientIpHeader` | 프록시가 실제 접속자 IP 를 적어 주는 헤더. **Caddy·nginx = `X-Forwarded-For`, Cloudflare 터널 = `CF-Connecting-IP`**, 프록시 없이 직접 받으면 `none` | X-Forwarded-For |
| `premiumMode` | `allowlist` = premium.txt 의 계정만 / `open` = 로그인한 누구나 | allowlist |
| `maxSessionsPerAccount` | 한 계정이 동시에 잠수할 수 있는 서버 수 | 2 |
| `maxServersPerAccount` | 한 계정이 저장할 수 있는 서버 수 | 20 |
| `maxActiveSessions` | 전체(본 서버 + 접속용 서버를 모두 합쳐)에서 동시에 돌릴 잠수 수 | 200 |
| `maxAccountsPerTarget` | **같은 마인크래프트 서버에** 클라우드에서 동시에 들어갈 계정 수 (0 = 제한 없음). 접속용 서버를 늘려도 이 수는 **전체 합계**입니다 | 3 |
| `targetLimits` | 서버별로 다르게: `주소=수` 를 쉼표로 | (비어 있음) |
| `dataDir` | 데이터 폴더 | data |
| `localWorker` | 이 프로그램 안에서도 잠수를 돌릴지. 접속용 서버에서만 돌리려면 `false` (16번) | true |
| `localCapacity` | 이 프로그램 안에서 돌릴 최대 잠수 수 | `maxActiveSessions` 와 같음 |
| `workerPort` | 접속용 서버가 붙는 포트. `0` = 받지 않음 (16번) | 0 |
| `workerBind` | 그 포트를 여는 주소 | 0.0.0.0 |

설정을 바꾸면 서버를 다시 켜야 적용됩니다.

## 5. 유료(프리미엄) 사용자 관리
`premiumMode=allowlist` 이면 **`data/premium.txt` 에 적힌 계정만** 클라우드 잠수를 쓸 수 있습니다. 이 파일은 저장하면 **바로 반영**됩니다(서버를 끌 필요 없음).

```
# 한 줄에 한 명: 닉네임 또는 UUID, 그 뒤에 만료일(선택)
Steve                       # 기한 없음
Alex 2027-01-31             # 2027년 1월 31일까지
```

명령으로도 넣을 수 있습니다 (서버가 켜져 있어도 됩니다. `cloud.properties` 가 있는 폴더에서 실행).
```bash
bin/jamsu-cloud grant Steve 30
```
```bash
bin/jamsu-cloud revoke Steve
```

- 프리미엄이 아닌 사람이 로그인하면 **닉네임과 UUID** 가 화면에 나옵니다 → 그 닉네임을 받아 premium.txt 에 적어 주면 됩니다.
- 프리미엄이 아닌 계정의 로그인 정보는 서버에 저장하지 않습니다. (예전에 프리미엄이었던 계정이 프리미엄 없이 다시 로그인하면 남아 있던 정보도 그때 지웁니다)
- 기간이 끝나면 5분 안에 그 계정의 잠수가 멈춥니다. **그 뒤 7일 동안 프리미엄이 다시 생기지 않으면 저장된 로그인 정보·서버 목록을 지웁니다** (그 안에 다시 넣어 주면 그대로 이어 씁니다).
- 닉네임은 바뀔 수 있으니 오래 쓸 사람은 UUID 로 적는 것이 안전합니다.

## 6. 인터넷에 공개하기 (HTTPS 필수)
로그인 정보와 채팅이 오가므로 **반드시 HTTPS** 로만 공개하세요. 앱은 `https://` 주소만 받습니다(같은 공유기 안의 `http://192.168.x.x` 는 시험용으로 허용).
`bind=127.0.0.1` 은 그대로 두고 앞에 아래 둘 중 하나를 둡니다.

**방법 A — Cloudflare 터널 (공유기 설정이 필요 없어 집 컴퓨터에 편함)**
도메인을 Cloudflare 에 연결한 뒤 `cloudflared` 를 설치하고 터널의 대상을 `http://localhost:8787` 로 지정합니다.
`cloud.properties` 에 **`clientIpHeader=CF-Connecting-IP`** 를 적어 주세요. 집 컴퓨터의 실제 IP 가 드러나지 않는 장점도 있습니다.
(Cloudflare 문서: https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/ )

**방법 B — Caddy (도메인 + 공유기 포트 포워딩 80·443)**
`Caddyfile` 한 줄이면 인증서를 자동으로 받아 줍니다.
```
cloud.example.com {
    reverse_proxy 127.0.0.1:8787
}
```
`clientIpHeader=X-Forwarded-For` (기본값) 그대로 두면 됩니다. (Caddy 문서: https://caddyserver.com/docs/quick-starts/reverse-proxy )

> `clientIpHeader` 는 쓰는 프록시에 맞는 것 **하나만** 적어야 합니다. 맞지 않으면 "로그인 시도 횟수 제한" 같은 보호 장치를 접속자가 피해 갈 수 있습니다.

> 실시간 표시(SSE)를 쓰므로 프록시가 응답을 모아서 보내지 않게 해야 합니다. Caddy·Cloudflare 터널은 기본 설정으로 됩니다. nginx 를 쓰면 `proxy_buffering off;` 가 필요합니다.

## 7. 앱에서 쓰기
1. 앱 **설정 → 클라우드 잠수 (프리미엄)** → 주소에 `https://내주소` 입력 → **확인**
2. 아래 계정 줄의 **연결** → 안내를 읽고 **동의하고 연결**
   (이 계정의 로그인 정보가 클라우드 서버로 넘어가 암호화되어 저장됩니다. 앱 v2.0.0 이상에서 로그인한 계정만 됩니다 — 그 전에 추가한 계정은 계정 관리에서 지우고 다시 로그인한 뒤 연결하세요)
3. 서버 설정에서 **클라우드에서 잠수** 를 켜고 저장 → 목록에 `☁ 클라우드` 가 붙습니다.
4. **시작** 을 누르면 클라우드에 요청이 가고, 채팅 화면에 클라우드의 채팅이 실시간으로 보입니다.

- 모든 사용자의 앱에 주소를 미리 넣으려면 GitHub 저장소 **Variables** 에 `CLOUD_URL` = `https://내주소` 를 등록하면 다음 빌드부터 기본값으로 들어갑니다.
- 앱의 클라우드 잠수 화면에서는 아직 **지도·이동·아이템 사용** 을 쓸 수 없습니다 (이동은 웹 화면의 이동 탭에서 됩니다). 채팅·명령어·자동완성·서버 메뉴 클릭·접속자·체력·사망 알림·칭호 그림은 됩니다.
- 앱을 안 보는 동안에는 폰이 클라우드와 연결하지 않습니다(배터리·데이터 절약). 그동안의 채팅은 앱을 열면 이어서 받습니다(서버마다 최근 1,500줄).

## 8. 웹에서 쓰기
브라우저에서 주소를 열고 **마이크로소프트 계정으로 로그인** → 화면의 코드를 복사 → 마이크로소프트 페이지에 붙여 넣고 로그인하면 됩니다.
서버 추가·설정·시작·끊기, 채팅, 접속자·상태 보기가 되고, 아래 기능이 있습니다. **계정 → 연결 해제(삭제)** 를 누르면 그 계정의 잠수를 모두 끊고 서버에 저장된 정보를 지웁니다.

| 기능 | 쓰는 법 |
|---|---|
| **이동** | **이동** 탭의 조이스틱을 끌거나(위쪽 = 북쪽) 키보드 `W A S D`·방향키, 점프는 버튼·스페이스. 좌표와 월드 이름이 위에 보입니다. 손을 떼면 바로 멈추고, 탭을 닫거나 연결이 끊겨도 1.5초 뒤 스스로 멈춥니다. 지도는 아직 없습니다 |
| **메뉴 열기** | 서버가 상자 같은 메뉴 창을 띄우면 채팅 위에 "서버 메뉴: (제목)" 줄이 뜹니다 → **열기** → 아이템을 눌러 클릭, **메뉴 닫기** 로 닫기 |
| **자동 클릭** | 메뉴 창의 아이템 아래 **＋ 자동 클릭에 추가** 를 누르면 다음부터 그 메뉴가 열릴 때 자동으로 누릅니다. 서버 **설정 → 메뉴 자동 클릭** 칸에 `메뉴 제목 > 아이템 이름` 을 직접 적어도 됩니다 (다음 접속부터 적용) |
| **자동 접속** | 서버 **설정** 의 "끊기면 자동 재접속"·"킥당해도 재접속" (기본 켜짐). 서버 컴퓨터를 껐다 켜도 잠수하던 서버에 이어서 접속합니다. "접속 후 자동 실행" 에 적은 명령어는 접속할 때마다 차례로 보냅니다 |

- **코드는 본인만 입력해야 합니다.** 다른 사람이 보내 준 코드를 마이크로소프트 페이지에 입력하면 그 사람이 내 계정의 잠수를 조작할 수 있게 됩니다(이 로그인 방식의 알려진 약점). 사용자들에게도 알려 주세요.
- 새 기기가 로그인하면 이미 로그인해 있던 화면(웹·앱)에 알림이 뜹니다. **계정** 창의 기기 목록에서 모르는 기기를 **로그아웃**시킬 수 있습니다.

## 9. "어디서 실행 중인지" 표시와 중복 접속 차단
같은 계정이 같은 마인크래프트 서버에 두 곳에서 들어가면 서로 튕겨 내므로, 먼저 들어간 쪽이 있으면 막습니다.

| 지금 접속 중인 곳 | 다른 곳에서 시작하려 하면 |
|---|---|
| **클라우드** | 폰 앱(직접 잠수): "이미 클라우드에서 실행 중입니다. 그쪽 연결을 해제하고 다시 시도해 주세요" + [클라우드 연결 끊기] 버튼 |
| **폰 앱**(직접 잠수) | 클라우드(웹·앱에서 시작): "이미 앱 · (기기 이름)에서 실행 중입니다. 그쪽 연결을 해제하고 다시 시도해 주세요" |
| **PC 게임 등 다른 클라이언트** | 그쪽이 들어오면 마인크래프트 서버가 클라우드·앱 쪽을 내보냅니다 → 잠수를 멈추고 "다른 클라이언트(PC 게임 등)에서 접속해 끊겼습니다" 로 표시. 30분 안에 다시 시작하면 "지금 시작하면 그쪽 접속이 끊깁니다. 계속할까요?" 를 묻습니다 |

- 웹은 따로 접속하는 매체가 아니라 **클라우드 잠수를 보는 화면**입니다.
- **PC 게임이 들어가는 것 자체는 막을 수 없습니다** (게임은 우리 서버를 거치지 않습니다). 막으려면 PC 쪽 모드(FastPack)가 접속 전에 클라우드에 물어보게 만들어야 합니다 — 아직 없음.
- 폰 앱은 직접 잠수 중인 서버를 1분마다 클라우드에 알립니다. 폰이 갑자기 꺼지면 2분 30초 뒤에 "앱에서 실행 중" 표시가 풀립니다.

## 10. 같은 IP 문제 (여러 사람이 한 마인크래프트 서버에 들어갈 때)
클라우드의 모든 계정은 **잠수를 돌리는 컴퓨터의 IP**로 나갑니다 (컴퓨터가 한 대면 IP 하나). 마인크래프트 서버 대부분은 "같은 IP 에서 몇 명까지" 제한이 있어서, 넘기면 부계정으로 처리하거나 IP 를 통째로 막을 수 있습니다.
- `maxAccountsPerTarget` 으로 서버 하나에 들어갈 계정 수를 그 제한보다 낮게 둡니다. 자리가 차면 "지금 이 서버는 클라우드 자리가 모두 찼습니다" 라고 안내합니다.
- 운영진에게 "이 IP 는 여러 사용자가 쓰는 잠수 서비스" 라고 알리고 **허용을 받은 서버**만 `targetLimits=주소=수` 로 늘립니다.
- 접속용 서버(16번)를 붙이면 한 마인크래프트 서버의 인원이 여러 컴퓨터에 고르게 나뉘어 IP 하나에 몰리지 않습니다. 그래도 **`maxAccountsPerTarget`·`targetLimits` 는 컴퓨터 수와 상관없는 전체 합계**입니다 — 컴퓨터를 늘린다고 한 서버에 더 많이 들어가지는 않습니다. 더 넣으려면 그 서버 운영진의 허용을 받아 수를 직접 올려야 합니다.
- 계정마다 IP 를 다르게 보이게 하는 방식(프록시)은 넣지 않았습니다. 서버의 제한을 속이는 것이라 규칙 위반이고, 적발되면 사용자 계정이 정지됩니다.
- 한꺼번에 많은 계정이 로그인하면 모장 인증 서버의 요청 제한(429)에도 걸립니다. 서버를 다시 켤 때는 2초 간격으로 차례로 접속합니다.

## 11. 업데이트
1. 서버를 끕니다 (Ctrl+C. 잠수 중이던 서버는 기억해 두었다가 다시 켜면 2초 간격으로 이어서 접속합니다)
2. 새 `jamsu-cloud.zip` 을 같은 자리에 **덮어 풉니다** (`bin`·`lib`·안내문이 바뀝니다). 압축 안에는 `cloud.properties` 와 `data/` 가 없으므로 설정과 데이터는 그대로 남습니다.
3. 다시 켭니다.

접속용 서버를 쓰고 있다면 **본 서버와 접속용 서버를 같은 버전으로** 맞춥니다. 본 서버를 먼저 바꾸고 접속용 서버를 하나씩 바꾸면 됩니다 (형식이 달라진 업데이트에서는 버전이 다른 접속용 서버를 본 서버가 받지 않고, 접속용 서버 로그에 그 이유가 찍힙니다).

켜져 있는 동안 파일을 덮어쓰면 오류가 나니 꼭 끄고 바꾸세요. 앱이 서버보다 새 버전이어도 대부분 동작하지만, 형식이 바뀌는 업데이트 때는 앱이 "클라우드 서버를 업데이트해 주세요" 라고 알려 줍니다.

## 12. 데이터와 보안
```
data/
  master.key        ← 로그인 정보를 암호화하는 키. 절대 공유·업로드하지 마세요
  accounts/         ← 계정 + 암호화된 마이크로소프트 로그인 정보
  servers/          ← 계정별 서버 목록, 잠수 중 표시
  tokens.json       ← 로그인한 기기들 (토큰은 해시만 저장)
  premium.txt       ← 프리미엄 목록
  engine/           ← 버전 변환기 설정
  worker.key        ← 접속용 서버를 받을 때(workerPort)만 생김. 접속용 서버가 본 서버에 붙을 때 쓰는 비밀키. 공유·업로드 금지
```
- 마이크로소프트 로그인 정보는 `master.key` 로 암호화(AES-256-GCM)해 저장합니다. **`data/` 폴더 전체가 새어 나가면 계정이 위험**하므로 이 컴퓨터의 접근 권한을 잘 관리하세요.
- 채팅은 디스크에 저장하지 않습니다 (메모리에 서버마다 최근 1,500줄. 서버를 끄면 사라짐).
- 사용자가 **연결 해제(삭제)** 를 누르면 그 계정의 로그인 정보·서버 목록·기기 기록을 바로 지웁니다.
- 사용자가 적은 주소로 이 컴퓨터가 대신 접속하므로, 내부망 주소(192.168.x.x 등)·이 컴퓨터 자신의 주소·같은 IPv6 대역(집 안의 다른 기기)과 1024 미만 포트로는 접속하지 않게 막아 두었습니다.
- 사용자가 접속한 마인크래프트 서버에는 **이 컴퓨터의 IP 가 보입니다** (Cloudflare 터널로 웹 주소를 가려도 마찬가지).
- 악의적인 마인크래프트 서버가 비정상적인 채팅·메뉴·접속자 목록을 보내 서비스를 느리게 만들지 못하도록 해석량·크기에 한도를 두었습니다. 메모리가 바닥나면 프로그램이 스스로 꺼지게 해 두었으니(`-XX:+ExitOnOutOfMemoryError`) 13번의 자동 시작을 꼭 설정해 두세요.
- 윈도우에서는 `data` 폴더의 접근 권한을 프로그램이 좁혀 주지 못합니다. 다른 사람이 쓰는 컴퓨터라면 폴더 권한을 직접 잠가 두세요.

## 16. 접속용 서버 붙이기 (컴퓨터를 여러 대로 늘릴 때, v2.1.0~)
컴퓨터 한 대로 모자랄 때(메모리, 또는 한 IP 에 사람이 몰리는 것) **같은 프로그램을 다른 컴퓨터에서 "접속용 서버"로** 띄워 잠수를 나눠 돌립니다.

```
 폰 앱 ─┐                      ┌─ (본 서버 안에서 직접)  ─┐
        ├─(HTTPS)─ 본 서버 ────┤                          ├─ 마인크래프트 서버들
 웹 ────┘  로그인·목록·배정     ├─ 접속용 서버 A (다른 IP) ─┤
                               └─ 접속용 서버 B (다른 IP) ─┘
```

- **본 서버**: 지금까지 쓰던 그 서버입니다. 웹·앱이 붙고, 로그인 정보·서버 목록·프리미엄·인원 제한을 모두 여기서 관리합니다. 주소·데이터·사용법은 그대로입니다.
- **접속용 서버**: 본 서버가 시키는 잠수를 대신 돌리기만 합니다. 웹 화면이 없고, **로그인 정보를 디스크에 저장하지 않습니다** (접속할 때마다 본 서버에서 받아 메모리에서만 씁니다).
- 접속용 서버가 **본 서버 쪽으로 먼저 연결**합니다. 그래서 접속용 서버 쪽은 포트를 열 필요가 없고, 본 서버만 `workerPort` 하나를 열면 됩니다.
- 컴퓨터가 한 대뿐이면 이 기능은 필요 없습니다. 아무 설정도 바꾸지 않으면 전과 똑같이 동작합니다.

### 본 서버에서
1. `cloud.properties` 에 `workerPort=8788` (원하는 포트)을 적고 다시 켭니다.
2. `data/worker.key` 파일이 생깁니다. 이 안의 한 줄이 **비밀키**입니다.
3. 방화벽·공유기에서 그 포트(TCP)를 **접속용 서버의 IP 에서만** 들어올 수 있게 엽니다. 이 포트는 Cloudflare 터널·Caddy 를 거치지 않는 별도 연결입니다(웹 주소와 무관).

### 접속용 서버에서
1. 자바 17 과 같은 `jamsu-cloud.zip` 을 풉니다 (본 서버와 **같은 버전**).
2. 한 번 실행하면 `worker.properties` 가 만들어지고 꺼집니다.
   ```bat
   bin\jamsu-cloud.bat worker
   ```
   ```bash
   bin/jamsu-cloud worker
   ```
3. `worker.properties` 를 채우고 다시 실행합니다.

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `master` | 본 서버의 `주소:포트` (본 서버의 `workerPort`) | (꼭 적기) |
| `secret` | 본 서버 `data/worker.key` 의 내용 그대로. **이 파일에 비밀키가 그대로 적히므로** `worker.properties` 도 `worker.key` 처럼 다루세요 (다른 사용자가 읽지 못하게, 공유·업로드 금지) | (꼭 적기) |
| `name` | 이 접속용 서버의 이름 (영문·숫자·`-`·`_`, 64자까지, 서로 달라야 함. `local` 은 본 서버 안의 실행기 이름이라 쓸 수 없음). 본 서버 로그에 이 이름으로 보입니다 | 컴퓨터 이름 |
| `capacity` | 이 컴퓨터에서 동시에 돌릴 잠수 수 | 200 |
| `dataDir` | 버전 변환기 설정을 둘 폴더 | data |
| `allowPrivateTargets` | 내부망 주소의 마인크래프트 서버 접속 허용 (시험용) | false |

본 서버 로그에 `[노드] 연결됨: 이름 (자리 200, …)` 이 보이면 붙은 것입니다. 그 뒤로 잠수를 시작할 때마다 `[배정] 닉네임/서버 → 이름` 으로 어디에 맡겼는지 찍힙니다.
붙지 못하면 **양쪽 로그**에 사유가 남습니다: 본 서버 `[노드] 거절: 이름 (IP) — 사유`, 접속용 서버 `[노드] 본 서버가 거절했습니다: 사유` (비밀키가 다름 / 버전이 다름 / 같은 이름이 이미 붙어 있음).

### 어디에 맡기나
- 같은 마인크래프트 서버에 들어가 있는 잠수가 **가장 적은 곳**에 먼저 맡깁니다 (한 서버의 인원이 여러 IP 로 고르게 나뉨). 같으면 자리가 더 많이 남은 곳입니다.
- 본 서버 안에서는 돌리지 않으려면 `localWorker=false` (본 서버는 관리만, 잠수는 접속용 서버에서만). 본 서버에서 돌릴 수를 줄이려면 `localCapacity` (적지 않으면 `maxActiveSessions` 와 같아서, 접속용 서버를 붙여도 본 서버가 그만큼까지 받습니다 — 본 서버의 메모리가 모자라면 줄이세요).
- `maxActiveSessions`(전체 수)·`maxAccountsPerTarget`·`targetLimits`(서버별 계정 수)는 **컴퓨터를 몇 대 붙이든 전체 합계**로 셉니다.
- 계정마다 IP 를 바꿔 서버의 제한을 피하는 용도로 쓰는 기능이 아닙니다(10번). 사용자·잠수를 특정 IP 에 고정하거나 고르는 설정은 없습니다.

### 끊겼을 때
- **접속용 서버가 꺼지거나 연결이 끊기면**: 거기서 돌던 잠수는 화면에 "접속용 서버 연결이 끊겨 다른 곳에서 다시 접속합니다" 로 바뀌고, **30초 뒤** 자리가 있는 다른 곳에서 2초 간격으로 다시 접속합니다. (30초를 기다리는 이유: 연결만 끊기고 접속용 서버가 살아 있는 경우 그쪽이 스스로 잠수를 끊는 데 15초가 걸립니다. 바로 옮기면 한 계정이 두 곳에서 접속해 서로 튕겨 냅니다.)
- **자리가 없으면**: "접속할 자리를 기다리는 중…" 으로 10초마다 다시 알아봅니다. 10분이 지나도 없으면 "접속할 자리가 없어 멈췄습니다" 로 멈춰 두었다가, 접속용 서버가 다시 붙거나 본 서버를 다시 켜면 이어서 접속합니다. 기다리는 동안 사용자가 끊기를 누르면 그대로 멈춥니다.
- 자리가 없을 때 **새로 시작하는 잠수**는 기다리지 않고 "지금 클라우드 서버가 가득 찼습니다" 로 거절합니다.
- 한 잠수가 10분 안에 3번 넘게 옮겨지면(접속용 서버가 계속 끊겼다 붙었다 할 때) "접속용 서버가 자주 끊겨 잠수를 멈췄습니다" 로 멈춥니다 — 로그인이 끝없이 반복돼 모장 요청 제한에 걸리는 것을 막기 위해서입니다. 갑자기 끊긴 것만 세고, 접속용 서버를 정상 종료(Ctrl+C)해서 옮겨진 것은 세지 않습니다.
- **본 서버가 꺼지거나 연결이 끊기면**: 접속용 서버는 돌리던 잠수를 **모두 끊고** 본 서버에 다시 붙기를 기다립니다(5·10·30·60초 간격). 본 서버가 다시 켜지면 "잠수 중"이던 것들을 이어서 접속시킵니다. 즉 **본 서버가 꺼져 있는 동안은 잠수가 유지되지 않습니다** — 본 서버 컴퓨터를 가장 안정적인 곳에 두세요.
- 접속용 서버를 Ctrl+C 로 끄면 본 서버에 알리고 꺼지므로 기다리는 시간 없이 바로 다른 곳으로 옮겨집니다 (업데이트할 때는 이렇게 끄세요).
- 사용자가 **끊기**를 눌렀는데 마침 그 접속용 서버와의 연결이 죽어 있었다면, 끊김이 확인되는 대로(길어도 15초) 그대로 멈춥니다. 다른 곳에서 되살아나지 않습니다.

### 보안
- 본 서버와 접속용 서버 사이의 연결은 비밀키로 **서로를 확인하고 전체를 암호화**합니다(AES-256-GCM, 연결마다 새 키). 비밀키가 없는 쪽은 붙을 수 없고, 가짜 본 서버에도 붙지 않습니다.
- **`worker.key`(=`secret`)가 새면** 누구든 접속용 서버인 척 붙어서, 자기에게 배정된 잠수의 접속용 토큰(마인크래프트 접속에 쓰는 짧은 수명 토큰)을 받을 수 있습니다. 새었다고 의심되면 본 서버를 끄고 `data/worker.key` 를 지운 뒤 다시 켜면 새 키가 만들어집니다 (접속용 서버들의 `secret` 도 새 값으로 바꿔야 함).
- 접속용 서버에는 마이크로소프트 로그인 정보(갱신 토큰)가 가지 않습니다. 접속할 때 쓰는 토큰만 그때그때 받아 메모리에서 쓰고, **자기에게 배정된, 지금 돌고 있는 잠수의 것만** 받을 수 있습니다 (끊었거나 다른 곳으로 옮겨진 잠수의 토큰은 더 주지 않습니다).
- 그래도 접속용 서버를 돌리는 컴퓨터의 주인은 그 컴퓨터에서 도는 잠수의 채팅·토큰을 볼 수 있는 위치에 있습니다. **믿을 수 있는 컴퓨터에만** 띄우고, 남의 컴퓨터·호스팅을 쓴다면 개인정보처리방침의 위탁 항목에 적어야 합니다(14번).
- 접속용 서버 쪽에도 13번의 자동 시작을 설정해 두세요 (실행 명령 끝에 `worker` 만 붙이면 됩니다).
