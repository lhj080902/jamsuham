## 1. 의도
Google Play 심사(비공개 테스트 → 프로덕션)를 통과하려는 것이 목적이다. 걸리는 것이 둘 있다.

1. **심사자가 로그인하지 못한다.** 앱은 정품 마이크로소프트 계정으로만 접속되는데, 마이크로소프트는 처음 보는 기기의 로그인에 메일 코드를 요구하고 이것은 끌 수 없다(2026-11-27 사용자 확인: "거의 완료… 본인 여부를 확인하는 단계가 한번 더 있습니다"). Play 규정은 코드 단계를 건너뛸 수 있는 로그인 정보를 요구한다 → 로그인 없이 앱 기능을 써 볼 수 있는 **체험 모드**를 넣는다.
2. **사용자 제작 콘텐츠(UGC) 정책.** 다른 플랫폼의 UGC 를 보여 주는 클라이언트 앱도 대상이며, 요구는 ① 이용 약관 동의(건너뛸 수 없음, 개인정보처리방침과 별개) ② 금지 콘텐츠 정의 ③ 사용자·콘텐츠를 **신고**하고 **차단**하는 앱 안 기능이다. 지금 앱에는 셋 다 없다.

같은 빌드에 사용자가 전에 요청한 **아이템 버리기 잠금**과 **왕복형 이름**을 함께 넣는다 (Play 에 올릴 때마다 심사를 받으므로 한 번에).

## 2. 목표 / 비목표 / 반목표
**목표**
1. 계정·인터넷 없이, 첫 화면에서 두 번 누르면(체험 추가 → 시작) 채팅·지도·이동·인벤토리(사용·버리기)·접속자·상태·메뉴·잠수 알림(화면 꺼도 유지)을 실제 동작 그대로 써 볼 수 있다.
2. 체험은 실제 서버에 붙을 때와 **같은 코드 경로**(`AfkService` → `SessionHub.start` → `AfkSession` → `McConnection`)를 탄다. 화면만 흉내 내지 않는다.
3. 접속자 탭의 모든 접속자(나 제외) 옆에 [차단]·[신고]가 따로, 이름이 분명하게 있다. 채팅 줄에서도 그 줄을 신고·숨기고 쓴 사람을 차단할 수 있다.
4. 첫 실행(그리고 약관이 바뀐 뒤 첫 실행) 때 이용 약관에 동의해야 앱을 쓸 수 있다.
5. 잠근 아이템은 버릴 수 없다 (서버별로 기억).
6. 접속자 탭에서 잘리는 이름은 끝까지 갔다가 되돌아오는 방식으로 움직인다.
7. Play 판은 클라우드 잠수를 숨긴다. 그래서 Play 판이 개발자 쪽으로 보내는 데이터는 없다 (데이터 보안 신고 "수집 안 함").

**비목표 (이번에 안 함)**
- 앱 사용자에게만 신고 버튼 표시 (누가 이 앱을 쓰는지 알려면 중앙 서버로 닉네임·접속 서버를 보내야 함 → 데이터 수집, 잠수 앱 사용자 노출)
- 마인크래프트 공식 채팅 신고(Mojang) 연동, 서버 쪽 제재, 욕설 자동 걸러 내기
- 웹(클라우드) 화면의 차단·신고, 클라우드 잠수 화면의 지도·이동
- 스크린샷 촬영(`screenshots.yml`)을 체험 서버로 바꾸기 (지금처럼 node 시험 서버 사용)
- 개인정보처리방침 영어판

**반목표 (이렇게 되면 실패)**
- 체험용 비정품 이름 접속으로 **실제 서버**에 들어갈 수 있게 됨 (v1.7.1 에서 뺀 비정품 접속이 되살아남)
- 체험 서버가 기기 밖에서 접속 가능 (loopback 이 아닌 주소에 열림)
- 신고·차단이 숨어 있어 찾기 어렵거나, 버튼 하나가 신고와 차단을 겸해 헷갈림
- 약관 동의를 건너뛰고 채팅을 보낼 수 있음
- 배포판에서 스크린샷 모드(`Screenshots.on`)가 켜짐
- 차단·신고·잠금 때문에 기존 잠수 동작(재접속, 자동 명령어, 메뉴 자동 클릭)이 달라짐

## 3. 제약
- 앱은 이 환경에서 실행할 수 없다 → 엔진·체험 서버는 PC 하네스로, 화면은 `:appcheck:compileKotlin`(github·play 둘 다)과 GitHub Actions 에뮬레이터로 확인한다. 마지막에 사용자가 실제 폰에서 한 번 눌러 본다.
- 앱 화면은 XML 없이 코드(`Ui.kt` 도우미), 문구는 `tr("한국어", "English")` 두 벌.
- 새 라이브러리 없이 (core 의 Netty·Gson·ViaVersion NBT 그대로).
- 앱은 항상 1.21.4(프로토콜 769)로 말한다 → 체험 서버도 1.21.4 로만 말하면 된다.
- 장면 정의는 `tools/test-server/showcase.js` 하나 (지어낸 서버 "바다마을 야생", 지어낸 닉네임만). 이 파일은 지금 `screenshots` 브랜치에만 있다 → 작업 브랜치는 `screenshots` 에서 딴다. `main` 병합·푸시는 공개 릴리스가 나가므로 사용자 확인 뒤에.
- 클라우드와 주고받는 JSON(`Wire`, `Wire.API`)은 바꾸지 않는다.
- 버전: `gradle.properties` `jamsuham.version=2.3.0` (큰 기능 → 가운데 자리).

## 4. 접근
### 4.1 체험 모드를 만드는 방법
| 방법 | 내용 | 판단 |
|---|---|---|
| **A. 앱 안의 연습용 서버 (선택)** | core 에 작은 마인크래프트 서버를 넣고 앱이 `127.0.0.1` 로 실제 접속 | 모든 탭·알림이 실제 동작. 인터넷·운영 서버 불필요. PC 하네스로 시험 가능 |
| B. 화면에 가짜 소식 넣기 | 접속 없이 `SessionHub` 에 채팅·접속자만 밀어 넣음 | 지도·이동·잠수 알림을 보여 줄 수 없고 실제 경로와 다른 코드가 생김 |
| C. 공개 체험 서버 | 개발자가 인터넷에 시험 서버를 계속 켜 둠 | 서버를 항상 운영해야 하고 꺼지면 심사 실패 |
| D. 그림으로 둘러보기 | 스크린샷을 앱 안에서 보여 줌 | 기능을 써 보는 것이 아님 |

사용자가 방식을 맡김("1번으로 진행하자") → A 로 간다 (내 판단).

### 4.2 신고가 가는 곳
| 방법 | 내용 | 판단 |
|---|---|---|
| **메일 (선택)** | 신고 내용을 채운 메일 작성 창을 연다. 보내는 것은 사용자 | 서버 불필요, 앱이 직접 보내는 데이터 없음 |
| 개발자 서버로 전송 | 앱이 신고를 서버 API 로 보냄 | 상시 서버 필요, 데이터 수집 신고 필요 |
| Mojang 신고 | 서명된 채팅 증거가 필요 | 앱이 서명 채팅을 다루지 않음, 범위가 큼 |

사용자가 승인한 모양: 모든 접속자 옆에 [차단]·[신고], 신고는 메일 + "서버 운영진에게도 신고하세요" 안내, 차단은 내 화면에서 숨김.

## 5. 설계
### 5.1 체험 서버 (core)
- 위치 `core/src/main/kotlin/kr/jamsuham/core/demo/` (안드로이드 의존 없음). 처음 쓸 때 켜지고 `127.0.0.1` 의 빈 포트에만 연다. 앱 프로세스가 사는 동안 유지, 여러 접속을 받아도 됨.
- **장면은 녹화해서 넣는다.** `showcase.js` 서버에 node 클라이언트로 붙어 서버가 보낸 패킷(로그인·설정·레지스트리·청크·접속자·인벤토리 등)을 순서·시간과 함께 파일로 떠서 `core/src/main/resources/jamsuham/demo/` 에 넣고, 체험 서버가 그대로 다시 보낸다. 압축·암호화는 쓰지 않는다. 이유: 레지스트리·청크를 손으로 다시 쓰지 않고, 스크린샷과 같은 장면 정의 하나를 쓴다.
  - 녹화 도구는 `tools/demo/` 에 두고 다시 만드는 방법을 `CLAUDE.md` 에 적는다. 앱의 기본 프로토콜(지금 769)을 올리면 다시 녹화한다.
  - 한국어·영어 두 벌(`showcase.js` 에 언어 선택 추가). 체험 서버는 `Lang.english` 에 맞는 것을 쓴다.
  - 크기: 두 벌 합쳐 1MB 이하.
- **살아 있는 부분 (녹화가 아닌 것)**
  - 서버 목록 핑: 소개 글·인원(37/100)·아이콘·버전 1.21.4 응답. 이 값들은 `showcase.js` 가 아니라 `screenshots.yml` 의 환경 변수와 `tools/screenshots/icons/sea.png` 에 있으므로 체험 서버 쪽에 따로 둔다 (소개 글은 한국어·영어, 아이콘은 core 리소스로 복사). 접속 전에 엔진이 핑을 먼저 하므로 핑 응답은 꼭 있어야 한다
  - 접속 순서: 로그인 응답 → (클라이언트 확인) → 설정 패킷 → (확인) → 플레이 패킷을 녹화된 시간 간격으로. keep-alive 는 주기적으로 직접 보냄
  - 채팅: 보낸 말을 `<Jamsu_Diver> 말` 로 되돌려 줌. `/잠수` → 안내 글, `/메뉴`·`/menu` → 메뉴 창 열기. 채팅에 누르면 `/메뉴` 가 실행되는 [메뉴 열기] 줄을 둔다
  - 메뉴: 아무 칸이나 누르면 무엇을 눌렀는지 채팅 한 줄 + 창 닫기
  - 인벤토리 버리기(창 0, THROW): 그 칸을 줄이거나 비운 결과를 다시 보냄. 사용(우클릭)은 채팅 한 줄로 답
  - 이동: 받은 위치를 그대로 받아들임 (되돌리지 않음)
- 체험 닉네임 `Jamsu_Diver` (스크린샷과 같음).
- 파일 형식, 패킷 쓰는 도우미, 내부 구조는 만드는 사람이 정한다.

### 5.2 체험 모드 (app)
- `ServerEntry.demo: Boolean = false` 추가. 체험 서버는 한 개만.
- **들어가는 곳**: ① 서버가 없을 때 첫 화면 카드에 `[로그인 없이 체험해 보기]` / `[Try without signing in]` ② 설정 화면에 `[체험 서버 추가]` / `[Add demo server]` (이미 있으면 안 보임). 누르면 목록에 `체험 서버` / `Demo server` 가 생기고(태블릿은 바로 선택) 사용자가 [시작]을 누른다.
- **시작**: `BaseActivity.startServer` 에서 체험이면 계정 확인·클라우드 확인을 건너뛴다. `AfkService` 는 체험이면 체험 서버를 켜고 그 주소(`127.0.0.1:포트`)·`fixedVersion=1.21.4`·`JoinCredentials.offline("Jamsu_Diver")` 로 `SessionHub.start` 를 부른다. 그 뒤는 일반 잠수와 같다 (알림, 무료 동시 1개 제한, 끊기).
  - 비정품 이름은 **이 경로에서만** 만들어진다. `AccountStore` 는 건드리지 않고(계정 목록에 안 나옴), 체험 항목의 주소는 사용자가 바꿀 수 없다.
- **고정 값**: `resumeOnBoot=false`, `cloud=false`, `packGlyphs=false`, `walkOnJoin=false`, 자동 명령어 `/잠수`.
- **표시**: 목록의 소개 줄·아이콘·인원은 체험 서버 핑으로. 계정 자리에는 `체험 · 로그인 필요 없음` / `Demo · no sign-in needed`. 서버 설정 화면은 체험이면 이름 바꾸기와 삭제만 (주소·계정·클라우드·이어서 잠수 항목 숨김).
- 스크린샷 모드(`Screenshots`)는 그대로 둔다.

### 5.3 차단
- 저장: 앱 전체에서 하나(서버 공통), prefs `jamsuham_blocks`. 항목 = 닉네임(대소문자 무시) + UUID(알면) + 추가한 때.
- **효과**: 차단한 사람이 쓴 채팅 줄은 화면·채팅 기록 파일에 넣지 않는다. 차단하는 순간 이미 화면에 있는 그 사람 줄도 사라진다. 폰 잠수·클라우드 잠수 줄 모두 `SessionHub` 에 들어올 때 거른다.
- **누가 쓴 줄인지**: 줄의 글자만 보고 판단한다 (core·Wire 변경 없음). 규칙 = 줄 앞부분의 "작성자 자리"에 차단한 닉네임이 낱말 그대로 있으면 그 사람 줄.
  - 작성자 자리 = 처음 나오는 구분 글자(`> `, `: `, ` » `, ` -> ` 등) 앞까지, 없으면 앞 64자. 낱말 경계 = 영문·숫자·`_` 가 아닌 글자.
  - 예: `<Steve> 안녕`·`[VIP] Steve: 안녕`·`Steve -> 나: 안녕`·`Steve 님이 접속했습니다` 는 숨김 / `[공지] 관리자: Steve 는 정지되었습니다`·`<Steve_2> 안녕` 은 보임.
  - 이 판단 함수는 core(`text/`)에 두어 PC 하네스로 시험한다. 서버가 이름을 그림 글자·별명으로만 보여 주면 못 거를 수 있다 (알려진 한계, 문서에 적음).
- **화면**
  - 접속자 탭 한 줄: `[얼굴] 이름  핑  [차단] [신고]`. 내 줄에는 버튼 없음 — 지금 `PlayerPanel` 은 누가 나인지 모르므로 접속에 쓴 닉네임을 넘겨 **이름으로** 가린다 (체험 접속은 목록의 UUID 와 내 UUID 가 다르다). 차단한 사람은 이름을 흐리게 + `[차단 해제]`.
  - 설정 화면 "차단한 사용자": 목록과 [해제] (접속자 목록에 없는 사람도 풀 수 있게).
  - 채팅 줄 길게 누르기: 지금은 그림 글자 진단 창이 바로 뜸 → 메뉴로 바꾼다: `이 채팅 신고` / `이 채팅 숨기기` / `쓴 사람 차단` / `그림 글자 정보`(기존 진단). "쓴 사람 차단"은 줄에서 찾은 접속자 이름을 고르게 하고, 못 찾으면 닉네임을 직접 입력.
  - "이 채팅 숨기기"는 그 줄만 화면에서 지운다 (다시 접속하면 초기화).

### 5.4 신고
- 접속자 탭 [신고] 또는 채팅 줄 "이 채팅 신고" → 창: 사유 고르기(욕설·괴롭힘 / 스팸·광고 / 부적절한 닉네임·내용 / 기타), 설명(선택), `이 사용자도 차단`(기본 켜짐), 안내 글 "이 앱은 서버의 사용자를 제재할 수 없습니다. 서버 운영진에게도 신고해 주세요."
- [신고 보내기] → 메일 작성 창(`mailto:`)을 받는 사람·제목·본문을 채워 연다. 본문: 닉네임, UUID(알면), 서버 주소, 사유, 설명, 채팅 내용(채팅 줄 신고일 때), 시각, 앱 버전. 메일 앱이 없으면 내용을 복사하고 주소를 보여 준다.
- 받는 주소는 `AppInfo` 에 상수 하나로 (개인정보처리방침에 적힌 문의 주소와 같게 — 7번 미결).
- 앱이 직접 보내는 것은 없다 (사용자가 자기 메일로 보냄).

### 5.5 이용 약관
- 문서 `app/src/main/assets/legal/terms.md`(한국어)·`terms-en.md`(영어), 앱 언어에 맞춰 보여 준다. 들어갈 내용: 앱이 하는 일, 금지 행위(욕설·혐오·괴롭힘·성적 콘텐츠·아동 착취·불법 행위·스팸·사칭 — Play 정책에 맞게), 서버 규칙을 지킬 책임, 신고·차단 방법, 위반 시 조치, 면책, 문의 주소, 시행일.
- 동의 화면: 약관 버전(`TERMS_VERSION`, 1 부터)이 저장된 동의 버전보다 크면 모든 화면에 앞서 띄운다. 요약 + `[이용 약관 전문]`·`[개인정보처리방침]` 보기 + `[동의하고 시작]` / `[동의하지 않음]`(앱 닫기). 뒤로 가기·바깥 누르기로 닫히지 않는다.
- 기존 사용자도 업데이트 뒤 한 번 본다. **동의 검사는 화면에만 둔다** (내 판단): 업데이트·재부팅 때 이어서 시작되는 잠수(`BootReceiver`)와 사용자가 전에 넣어 둔 자동 명령어는 동의 전에도 그대로 돈다. 이유: 잠수 서비스에서 막으면 업데이트한 밤에 잠수가 말없이 멈춘다. Play 로 새로 설치한 사람은 화면을 거치지 않고는 잠수를 시작할 수 없으므로 항상 동의가 먼저다.
- 동의 버전은 하나(`TERMS_VERSION`)로 약관과 개인정보처리방침을 함께 덮는다. 둘 중 하나가 크게 바뀌면 올린다.
- "위반 시 조치"에 적을 내용: 개발자는 서버의 사용자를 제재할 권한이 없다는 것, 신고는 확인해서 앱 악용 파악·기능 개선에 쓰고 불법 콘텐츠는 관계 기관에 알릴 수 있다는 것, 약관을 어기는 용도로는 앱을 쓰지 말라는 것. 지킬 수 없는 약속(계정 정지 등)은 적지 않는다.
- 정보 화면(`AppInfo`)에 `[이용 약관]` 버튼 추가. 스크린샷 모드는 자동 동의.
- 약관 문구는 구현 때 초안을 써서 사용자에게 따로 보여 준다 (법률 검토를 거친 글이 아님).

### 5.6 아이템 버리기 잠금
- 잠금 단위 = **아이템 종류**: `itemId` + 서버가 붙인 이름(이름을 바꾼 아이템·서버 전용 아이템은 따로). 칸이 아니라 종류라서 게임에서 옮겨도 유지된다 (내 판단 — 사용자는 "아이템별 잠금"만 정함).
  - `MenuItem.name` 은 서버가 붙인 이름이 없으면 앱 언어의 기본 이름이 들어간다 → 그대로 쓰면 앱 언어를 바꿀 때 잠금이 풀린다. 그래서 이름이 그 `itemId` 의 기본 이름(한국어·영어 둘 다 비교)과 같으면 "이름 없음"으로 친다. `MenuItem`·`Wire` 에는 필드를 더하지 않는다.
- 서버별 저장: prefs `jamsuham_locks` (서버를 지우면 같이 지움). `ServerEntry` 와 따로 둔다.
- 화면(인벤토리 탭): 아이템을 펼치면 `[잠금]` / `[잠금 해제]`. 잠긴 아이템은 이름 옆에 `잠김` 표시, 버리기 버튼 자리에 "잠긴 아이템은 버릴 수 없습니다". 사용(우클릭)은 막지 않는다.
- 화면뿐 아니라 `SessionHub.dropItem` 에서도 막는다.

### 5.7 왕복형 이름
- 접속자 탭의 이름만 대상 (다른 곳의 `Ui.marquee` 는 그대로).
- 이름이 칸보다 길 때만: 잠깐 멈춤 → 끝이 보일 때까지 왼쪽으로 → 잠깐 멈춤 → 처음으로 되돌아옴을 되풀이. 짧으면 움직이지 않는다. 목록 줄이 재사용될 때·화면에서 사라질 때 멈춘다.

### 5.8 확인 방법
- `harness demo`: PC 에서 체험 서버를 켜고 핑 + `AfkSession` 접속 → 채팅 줄·접속자 8명·인벤토리 18칸·청크(지도 블록)·채팅 되돌림·`/메뉴`·메뉴 누르기·버리기 결과를 확인. `EN=1` 로 영어판도.
- `harness blockmatch`: 5.3 의 예시 줄들이 규칙대로 판단되는지.
- 기존 하네스(`showcase`, `drop`, `wire` 등)와 `:appcheck:compileKotlin -Pflavor=github|play` 가 그대로 통과.
- **에뮬레이터 확인**: 스크린샷 작업의 에뮬레이터 구성을 다시 써서, 스크린샷 모드가 **꺼진** Play 판 디버그 빌드로 약관 동의 → 체험 추가 → 시작 → 탭 넘기기 → 차단·신고 창 → 아이템 잠금까지 눌러 보고 화면을 그림으로 남긴다 (작업 브랜치에 올릴 때만 돈다, `main` 과 무관).
- 사용자: 제출 전에 실제 폰에서 체험 → 알림 → 화면 끄기 → 끊기 한 번.

### 5.9 문서·스토어
- `docs/store-listing.md`: 앱 액세스 안내(체험 방법 포함, 영어), 콘텐츠 등급 답(차단·신고 "예"), 약관 안내.
- `app/src/main/assets/legal/privacy-policy.md`: 신고 메일을 보내면 그 내용(상대 닉네임·UUID·채팅·서버 주소)이 개발자 메일로 전달된다는 것, 차단 목록·잠금·약관 동의 기록은 기기에만 저장된다는 것, 이용 약관 안내를 더한다.
- `CLAUDE.md`: 체험 서버·녹화 방법·차단/신고/약관/잠금 정리.
- 올린 뒤 사용자가 Play Console 에서 고칠 것: 콘텐츠 등급 설문의 차단·신고 항목, 로그인 세부정보.

### 5.10 Play 판에서 클라우드 잠수 숨김 (사용자 결정: 숨김)
- `Flavor.PLAY` 일 때: 설정 화면의 클라우드 잠수 카드, 서버 설정의 클라우드 스위치를 보이지 않게 하고 `CloudHub` 를 시작하지 않는다. GitHub 판은 그대로.
- Play 판은 새로 설치하는 사람뿐이라 `cloud=true` 인 서버 항목은 생기지 않는다.
- 그러면 `docs/store-listing.md` 의 데이터 보안은 "수집 안 함", 로그인 세부정보의 "모든 기능에 액세스" 체크도 사실과 맞는다.
- 클라우드 잠수는 나중에 Play 에 다시 넣거나 웹으로 따로 낼 수 있다 (이번 범위 아님). 그때는 데이터 보안 신고를 "수집함"으로 바꿔야 한다.

## 6. 위험
- 메일 신고 + 화면에서 숨기는 차단을 Google 이 충분하다고 볼지 문서에 없다. 반려되면 사유를 보고 고친다.
- 체험 모드가 "로그인 정보 제공" 요구를 대신한다고 Google 문서가 말하지는 않는다. 심사용 계정 정보도 함께 낸다.
- 녹화한 패킷을 그대로 다시 보내는 방식이 한 번에 안 될 수 있다 (압축 설정 패킷 제외, 설정 단계 순서). 하네스가 통과할 때까지 맞춘다.
